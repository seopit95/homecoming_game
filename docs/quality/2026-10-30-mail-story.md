# 관리사무소 미수령 우편과 원본 확인

2803호 부재로 관리실이 대신 받은 우편 3통을 하나의 보관대에 놓는다. 사진관의 가족사진 배송봉투, 생활지원 상담실의 배우자 동반 상담 회신, 관리사무소의 영상보존 통지다. 수신인·발송처·보관 사유를 각각 표시하고 입구의 수령 대장과 경비실 열쇠 기록도 같은 사유로 연결했다. 아내가 남편을 위해 여러 책상에 메시지를 배치했다는 설명은 제거했다.

사진은 결혼과 아이의 흔적, 상담 회신은 사업 실패 이후 아내의 일자리·생활 정리와 함께 도움을 받으려던 시도, 영상보존 통지는 남편의 삭제 요청과 보존된 시간대 목록을 드러낸다. 우편을 읽은 것만으로 사고 영상·전화 음성을 확인했다고 수첩에 쓰지 않는다. 기존 archive_road/call/gate ID와 저장·3통 수집·CCTV 해금·B1 탈출을 유지한다. 마지막 다시방 편지의 내용과 발견 연출은 그대로다.

CCTV는 도로 6초 → 통화 12초 → 입차 9초의 실제 원본을 차례로 재생하고 마지막 10초에 현재 관리실로 돌아온다(총 37초). 화면과 음향이 같은 프레임 함수를 사용하며 정지·재개도 보존한다. 원본 확인 전 수첩의 재생 시작 기록은 결론을 미리 공개하지 않는다. 현재 화면 전환 시 시계도 09→10으로 이어진다.

## 검증 범위

- 우편/보관대/해석/미션 UI/현행 CCTV 관련 최종 20개 검사 합격, 타입 검사 종료 0. 외부 증거 `mail-story-evidence/final-unit.txt`.
- 실제 Game 클래스의 현행 1F→열쇠→우편 3통→CCTV→B1 흐름, 안전한 조사·재개·엔딩 기록 4개 합격(`game-flow.txt`). 재생 순서·정지와 원본 완료·실제 모니터 4개 합격(`replay-green.txt`). 수첩의 결론 지연과 현재 화면 시계 회귀 3개 합격(`conclusion-green.txt`). 서로 겹치는 검사는 합산하지 않는다.
- 기존 stairs/resident/office 단정 6개는 수정 전 7482ab9와 수정 후 같은 이름으로 실패했다(`legacy-comparison.json`, 신규 실패 없음). 옛 수동 archiveReview 접근 2개도 변경 전후 동일하게 undefined.operate로 실패한다(`surveillance-before.txt`, `surveillance-after.txt`). 전체 suite 합격을 주장하지 않는다.
- HTML5 빌드 성공. 실제 브라우저 1280×720에서 한 보관대의 3봉투와 상담 회신 E 상호작용·목표 0/3→1/3·수첩 전문을 확인했다. 390×844에서는 수첩 가로 넘침 0과 스크롤을 확인했다. QA 체크포인트 주입은 로컬 서버 응답에만 있고 배포·ZIP에는 없다.
- 읽기 전용 코드 검토의 원본 재생 누락·수첩 정보 선행·혼합 음성 출처·시계 불연속 지적을 수정하고 해당 회귀를 확인했다. 입력·추격·음원 파일·마지막 편지는 바꾸지 않았다. 전체 캠페인·신규 플레이어 사용성·실제 휴대전화·직접 음향 청취는 이번 범위 밖이다.

사용자의 즉시 공개 배포 지시에 따라 기존 Sites의 공개 범위를 유지해 공식 소스/빌드/저장/배포 흐름을 사용한다. 배포 영수증과 최종 HTML5 해시·캡처는 task의 mail-story-evidence 및 itch-release/release-state.json에 남긴다. itch.io 업로드는 로그인 대기를 유지한다.

# 추격 음악의 고조와 수명 관리

기존 추격 경로와 음악 믹서를 유지하면서 새 오리지널 곡을 연결했다. `public/audio/chase-v143/pursuit.wav`는144BPM/26.667초/스테레오32kHz이며, 반음계 트레몰로 현악·저음 오스티나토·불협화음 브라스·직접 합성한 타악이다. 외부 녹음/곡/샘플은 쓰지 않았다. `scripts/compose-chase.py`와 동봉 sources.json에 재생성 조건·권리·SHA를 남겼다. 원래126BPM 파일은 보존하며 현재 게임은 새 URL만 요청한다. 새 WAV3,413,376바이트는 기존3,900,996보다487,620바이트 작다.

추격 강도0.5→1에 따라 곡 자체의 재생 속도1.05→1.1, 저역 통과2300→3700Hz, 추격 채널 목표0.425→0.85가 변한다. 시작의 시간상수0.18초와 종료0.65초로 부드럽게 연결한다. 상태가0이면 작은 변화량 억제와 무관하게 반드시 무음 목표를 설정한다. 한 Context에서 한 음악 source만 반복하며, 반복 추격·프레임 갱신은 같은 노드의 파라미터만 바꾼다. 음악·효과·목소리 버스는 기존대로 분리한다. 직접 작곡한 곡은 기존보다 낮은 채널 상한과 더 빠른 맥박/상부 현악으로 고조를 만든다.

## 확인한 범위

- 음향22개 검사 합격: 실제 HorrorAudio의 반복·고조·완전 종료 목표·중복 시작 방지·장치 정리·믹서·위치 음향·기존 후일담·브라우저 resume 거절/후속 제스처 복구. 새 고조 검사는 수정 전 곡 재생 속도가 변하지 않아 실패했다. native Web Audio 반환형에 맞게 근접 음향 fixture의 suspend/resume을 Promise로 갱신했다.
- 실제 Game 클래스4개 검사 합격: 계단/20층 추격의 음악 상태, 전화/플래시, 재시작 자원 유지, 컴파일 중 폐기. 기존 Game의 추격 판정·저장·진행은 바꾸지 않았다.
- 실제 Chromium AudioContext로 디코딩·재생 확인. 한 source가 약297초 동안 반복했고,60회 추격 상태 변경 뒤에도 sourceId1/시작1회였다. 약한 추격의 gain0.425/rate1.05에서 강한 추격의 gain0.85/rate1.1로 변했다. 정지 전후 contextTime80.5546667이 동일했고, 재개 뒤 음악0%에서도 효과/목소리 버스0.85를 유지했다. 종료 뒤 gain0, 해제 뒤 state=closed를 확인했다.
- 실제 게임20F 이어하기에서 새 곡이 재생되고 추격 중 gain이 올라가는 것, 사망 후 gain0.0003까지 감소, 재시도에도 sourceId1/시작1회, 메뉴에서 Context suspended를 확인했다. 로컬 QA checkpoint와 네이티브 Web Audio 관측은 서버 응답에만 주입하고 제품에 넣지 않는다.
- 파형은 클리핑0/루프 접점0/피크약0.602/RMS약0.117이다. 음량 여유와 버스 분리는 검증했으나 직접 청취는 환경에서 불가능했다. 공포감과 최종 스피커/헤드폰에서의 대사·발소리 가림은 사람의 청취 평가가 남는다. 모든 모바일/자동재생 정책을 인증한 결과는 아니다.

증거: task/loading-20261101의 chase-red/green.txt,chase-game-flow.txt,chase-render.txt,chase-native-controls.json 및 final-fast 서버의 native audio 관측. 타입/최종 빌드·공개 배포는 추가 엔딩 디자인과 합쳐 검증·기록한다.
